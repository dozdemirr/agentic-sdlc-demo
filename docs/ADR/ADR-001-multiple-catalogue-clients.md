# ADR-001: Multiple Catalogue Client Applications

- **Status:** Observed; rationale is [INFERRED].
- **Decision:** The repository contains separate Web Forms, MVC 5, ASP.NET Core-style MVC, and Windows Forms/WCF access paths over catalogue concepts. (Sources: `/eShopLegacyWebFormsSolution/eShopLegacyWebForms.sln`; `/eShopLegacyMVCSolution/eShopLegacyMVC.sln`; `/eShopLegacyNTier/eShopLegacyNTier.sln`; `/eShopLegacyMVCSolution/eShopPorted/eShopPorted.csproj`.)
- **Context:** The solutions expose the same general catalogue capabilities through different user interfaces and framework/runtime combinations. The README identifies the Web Forms portal, MVC storefront, and WCF-backed thick-client channel. (Sources: `/README.md`; `/eShopLegacyWebFormsSolution/src/eShopLegacyWebForms/Catalog/Details.aspx.cs`; `/eShopLegacyMVCSolution/src/eShopLegacyMVC/Controllers/CatalogController.cs`; `/eShopLegacyMVCSolution/eShopPorted/Controllers/CatalogController.cs`; `/eShopLegacyNTier/src/eShopWinForms/Program.cs`.)
- **Consequences:** Each implementation has its own entry points, configuration, and data-access code, while similar catalogue behavior appears in multiple projects. [INFERRED] This arrangement allows distinct channels to run independently but makes behavior changes potentially cross-project. (Sources: `/eShopLegacyWebFormsSolution/src/eShopLegacyWebForms/Services/CatalogService.cs`; `/eShopLegacyMVCSolution/src/eShopLegacyMVC/Services/CatalogService.cs`; `/eShopLegacyMVCSolution/eShopPorted/Services/CatalogService.cs`; `/eShopLegacyNTier/src/eShopWCFService/CatalogService.svc.cs`.)
