# ADR 0001: Separate Catalogue Application Implementations

- **Status:** Observed; inferred, not recorded as an explicit decision.

## Context

The repository contains Web Forms, MVC 5, ASP.NET Core MVC, and WCF/WinForms catalogue applications. Each has its own entry point, service types, configuration, and persistence context; the MVC 5 and ASP.NET Core applications are both members of the MVC solution but have separate project files. ## Observed decision

**[INFERRED]** The checked-in estate preserves separate application implementations rather than routing all user interfaces through one shared catalogue service. Similar catalogue functionality is repeated in application-specific service/context classes, while only the desktop application crosses an explicit WCF contract boundary. The repository does not state why these implementations remain separate or whether they are all actively deployed. Evidence: `/home/runner/work/agentic-sdlc-demo/agentic-sdlc-demo/eShopLegacyWebFormsSolution/src/eShopLegacyWebForms/Services/CatalogService.cs`; `/home/runner/work/agentic-sdlc-demo/agentic-sdlc-demo/eShopLegacyMVCSolution/src/eShopLegacyMVC/Services/CatalogService.cs`; `/home/runner/work/agentic-sdlc-demo/agentic-sdlc-demo/eShopLegacyMVCSolution/eShopPorted/Services/CatalogService.cs`; `/home/runner/work/agentic-sdlc-demo/agentic-sdlc-demo/eShopLegacyNTier/src/eShopWCFService/CatalogService.svc.cs`.

## Consequences visible in source

The same broad catalogue behavior is implemented across multiple services, each with its own EF context or WCF backing model. Their data paths and startup configuration differ, including EF6 versus EF Core, mock-selection values, and seeding mechanisms. These observations describe present code only and do not claim an intended future direction.
