# ADR-004: Entity Framework Persistence Per Application

- **Status:** Observed; rationale is [INFERRED].
- **Decision:** The Web Forms and MVC 5 applications use Entity Framework 6 contexts, `eShopPorted` uses Entity Framework Core, and the WCF service uses a separate Entity Framework 6 context. (Sources: `/eShopLegacyWebFormsSolution/src/eShopLegacyWebForms/Models/CatalogDBContext.cs`; `/eShopLegacyMVCSolution/src/eShopLegacyMVC/Models/CatalogDBContext.cs`; `/eShopLegacyMVCSolution/eShopPorted/Models/CatalogDBContext.cs`; `/eShopLegacyNTier/src/eShopWCFService/EntityModel.cs`.)
- **Context:** The classic web applications and WCF service use SQL Server LocalDB connection strings in their configuration, while the ported app has its own connection string in JSON settings. The EF6 contexts define related catalog schemas in separate projects, while the WCF context additionally models stock and discounts. (Sources: `/eShopLegacyWebFormsSolution/src/eShopLegacyWebForms/Web.config`; `/eShopLegacyMVCSolution/src/eShopLegacyMVC/Web.config`; `/eShopLegacyMVCSolution/eShopPorted/appsettings.json`; `/eShopLegacyNTier/src/eShopWCFService/Web.config`; `/eShopLegacyNTier/src/eShopWCFService/EntityModel.cs`.)
- **Consequences:** The data model and persistence logic are coupled to each application's framework-specific ORM context. [INFERRED] Changes to shared catalog concepts can require aligned edits across contexts because no shared model project is referenced by the application projects. (Sources: `/eShopLegacyWebFormsSolution/src/eShopLegacyWebForms/Models/CatalogDBContext.cs`; `/eShopLegacyMVCSolution/src/eShopLegacyMVC/Models/CatalogDBContext.cs`; `/eShopLegacyMVCSolution/eShopPorted/Models/CatalogDBContext.cs`; `/eShopLegacyNTier/src/eShopWCFService/EntityModel.cs`; `/eShopLegacyMVCSolution/eShopLegacyMVC.sln`; `/eShopLegacyNTier/eShopLegacyNTier.sln`.)
