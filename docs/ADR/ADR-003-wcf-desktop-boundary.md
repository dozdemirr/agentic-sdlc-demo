# ADR-003: WCF Boundary for the Desktop Client

- **Status:** Observed; rationale is [INFERRED].
- **Decision:** The Windows Forms client consumes catalog operations through a WCF `basicHttpBinding` service endpoint rather than accessing the service database directly. (Sources: `/eShopLegacyNTier/src/eShopWinForms/Program.cs`; `/eShopLegacyNTier/src/eShopWinForms/App.config`; `/eShopLegacyNTier/src/eShopWCFService/Web.config`; `/eShopLegacyNTier/src/eShopWCFService/ICatalogService.cs`.)
- **Context:** The WinForms startup creates a service client and passes it into the catalog controller. The WCF implementation owns the Entity Framework context and exposes catalog, stock, and discount operations. (Sources: `/eShopLegacyNTier/src/eShopWinForms/Program.cs`; `/eShopLegacyNTier/src/eShopWinForms/Controllers/CatalogController.cs`; `/eShopLegacyNTier/src/eShopWCFService/CatalogService.svc.cs`; `/eShopLegacyNTier/src/eShopWCFService/EntityModel.cs`.)
- **Consequences:** Desktop runtime depends on a reachable service endpoint and matching contract/proxy configuration. The checked-in endpoint is localhost-based, which indicates a local development setup; deployment-specific endpoint settings are not described here. (Sources: `/eShopLegacyNTier/src/eShopWinForms/App.config`; `/eShopLegacyNTier/src/eShopWinForms/Connected Services/eShopServiceReference/Reference.cs`; `/eShopLegacyNTier/src/eShopWCFService/Web.config`.)
